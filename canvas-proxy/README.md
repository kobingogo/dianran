# @kobinflow/canvas-proxy

点染的本地转发代理，用于浏览器无法直接访问的 AI 接口与 WebDAV 服务。配对协议 v2 需要网页与代理 0.2.0 配套使用；当前代码已准备，npm 发布与线上部署须一起安排。旧版开放代理不能通过新版连接测试。

## 本地使用

从项目根目录运行（Node.js >= 18.2）：

```bash
node canvas-proxy/index.js \
  --origin http://localhost:3000 \
  --target https://api.openai.com/v1
```

在「设置 → 高级 → 本地代理」打开开关。核对网页生成的命令后运行，选择「导入配对文件」，导入终端显示路径对应的 JSON，再测试连接。

正式配套发布后可将命令开头替换成 `npx @kobinflow/canvas-proxy@0.2.0`。也可安装已审阅的本地 npm 包。没有明确授权来源和服务时拒绝启动。

## 授权与配对

- 默认监听 `http://127.0.0.1:23210`；仅允许 `127.0.0.1`、`localhost` 或 `::1` 回环监听。`--port`、`--host` 及 `PORT` / `HOST` 保留；不能绑定 `0.0.0.0` 或公网地址。
- `--origin` 指定完整网页来源，协议、主机和端口都必须匹配，不包含页面路径。可重复传入；预检不能新增授权来源。
- `--target` 指定服务基础地址，可重复传入。授权按 URL origin 和路径段匹配：`https://api.example/v1` 可访问 `/v1/models`，不能访问 `/v10`、其他端口或其他域名。本地模型也必须显式授权，例如 `--target http://127.0.0.1:11434/v1`。
- 下载域名、WebDAV 等附加服务须单独授权；不根据接口返回的 URL 自动扩大权限。基础地址不能包含用户名、密码、查询或片段，拒绝可能绕过路径范围的编码分隔符和二次编码。
- 每个代理进程生成独立随机凭据，配对文件默认位于 `~/.dianran/proxy-pairing-<端口>-<进程>.json`，文件权限为 `0600`；可用 `--pairing-file <新文件路径>` 指定位置。凭据不输出到终端；退出时移除文件，重启后旧凭据失效。文件包含私密凭据，不是普通配置分享文件。
- 网页验证当前代理身份和协议后，把配对信息单独保存在当前站点的浏览器 localStorage；不会加入 AI 配置、配置分享或项目备份。更换代理地址、网页来源或增加服务后重新启动并配对。「移除配对」仅移除当前浏览器凭据；重启代理可撤销该进程的所有配对。

## 转发行为

转发地址仍采用 `http://127.0.0.1:23210/<完整目标URL>`。配对凭据只通过 `x-dianran-proxy-token` 头传给代理，绝不拼进 URL；该头及浏览器 Cookie、Origin、逐跳头不传给上游。渠道 API Key 仍由浏览器保管，通过渠道请求头传给已授权服务。

访问根路径 `/` 也需要已授权 Origin 与有效凭据，返回身份、协议及允许服务，不返回凭据。OPTIONS 仅对已授权来源与目标提供实际所需的预检响应，后续请求仍必须验证凭据。

请求方法、业务请求体、上游状态与有效响应头保持原样，SSE 流式透传。代理不跟随重定向，收到跳转返回可读的 `PROXY_REDIRECT_DENIED`；依赖跳转的渠道下载需要核对最终服务地址，不能假定已支持自动跨站下载。客户端断开会中断上游连接，不自动重试。

转发日志仅含方法、目标 origin、状态和耗时，不输出路径、查询参数、请求头、请求体、凭据或原始错误正文，不落盘日志。

## 连接失败

确认代理仍在运行，`--origin` 与地址栏的来源完全一致，目标在 `--target` 范围内；导入当前进程的配对文件。若浏览器拒绝本地网络访问，到该站点的权限设置允许“本地网络访问”，再测试连接。代理没有新增超时、重试、文件大小或并发限制。

## 可复现检查

```bash
node --test canvas-proxy/proxy.test.mjs web/tests/local-proxy.test.mjs
```

检查使用本机模拟上游，不调用付费模型。浏览器重放说明见仓库 `docs/T05-PROXY-VALIDATION.md`。
