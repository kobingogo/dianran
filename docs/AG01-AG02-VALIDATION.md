# AG01 / AG02 / AG04 服务端验证

## 实现边界

- 通信协议提升为 7；历史消息存储版本及文件保持独立，没有修改历史格式或迁移逻辑。
- 画布摘要返回 `target: { clientId, projectId, revision }`。外部 MCP 画布写入须带该目标；网页侧栏任务绑定发起项目，同一项目后续工具使用当前修订。切焦点不能重定向已有目标，切项目后须显式导航并重新读取。
- 待确认请求固化目标。网页上报项目或修订变化时取消等待/领取的旧请求。A→B→A 由网页提供新的修订身份，旧目标仍失效。
- `claimRequest` 原子领取一次，`validateRequest` 只允许已领取请求执行一次；终态只查询，不再执行。网页须在执行前同步新快照并核对本地目标。
- 状态区分等待、领取、执行、成功、失败、取消、过期与未知；现有 30 秒工具等待保持。等待中到期为过期，执行中到期为未知，SSE `tool_resolved` 清除执行入口。
- `canvas_get_request_status` 和 HTTP 集成使用的 `requestStatus` 查询原请求，超时错误包含可查询身份。回执在当前服务进程内保留，不冒充跨重启的永久执行日志。
- 正常结果带权威快照时先更新状态，再返回工具结果。执行超时后收到属于原项目的确切回执可以确认未知状态，但不采用迟到快照覆盖后续编辑。
- `canvas_get_state` / 选区读取明确为摘要；`canvas_export_snapshot` 保留完整正文但不含媒体原文件；`canvas_get_node_content` 按节点读取完整正文。图片原文件读取通过网页独立授权请求，视频和音频只声明元数据范围。
- `canvas_get_capabilities` 按模式向目标网页请求实际配置，不借用工作台连接状态。返回可选/已配置能力不等于真实生成成功，且不返回 Key。

## 可复现行为检查

```bash
./canvas-agent/node_modules/.bin/tsx --test canvas-agent/src/canvas/session.test.ts canvas-agent/src/canvas/operations.test.ts
```

42 项通过，涵盖原连接/对话/历史重放检查与新增以下场景：

- 未提供目标的外部写入拒绝；明确目标不随焦点变化。
- 项目切换和手动编辑取消旧修订请求；绑定任务读取不跟随新项目。
- 同一请求只能领取和执行一次；终态可查询，重复回执不产生操作。
- 模拟原 30 秒到期、停止、迟到批准和执行中回执丢失，状态可解释。
- 更新快照后连续读写能观察新修订。
- 执行超时后的迟到回执可确认结果，而不会覆盖后续快照。
- 长正文末尾保持；摘要明确截断；原媒体和凭证不从普通读取泄露。
- 图片读取须经单独网页授权；能力按模式发往精确目标。
