# AG03 / AG05 站点工具复核

## 本轮修复

- 工作台生成工具只确认指令排队，回执明确 `generation: queued`、`intentSaved: false`、`submitted: false`、`completed: false`，不再在网页消费指令前声称已经生成。
- 仅填写参数的指令返回 `not-requested`，没有付费任务提交回执。
- 查询支持 `unknown` 状态及统计，不将已确认的未知状态折算为失败。
- 查不到当前网页内存任务时明确 `not-observed`，不能把缺记录当成远端未执行或可直接重提的证明。
- 素材新增只有完成已有持久化入口后才返回 `saved: true`；存储异常继续传给 Agent，没有转换为成功。

## 独立审查反馈

画布 bridge 先提交业务变更、等待保存队列，再允许下游生成；保存失败不会回成功；撤销核对操作后的修订，已有后续编辑时拒绝恢复旧快照。保存等待期间发生新编辑时，生成前也须复核修订。

另向集成负责人指出需同步修复的路径：工作台意图/引用保存失败必须终结 Agent 的运行状态；网络未知或视频任务 ID 抢救状态须如实记录；批量生成应在最终图上核验目标，并拒绝同一节点在同一批中的重复生成。已在主集成中修复最终图重复/失效生成引用；工作台保存前失败不会遗留 running，网络未知保持 unknown。真实浏览器界面保存验收仍保留在 Pending Tests。本文件不替代它们的完成证据。

## 媒体原文件校验

新增 `validateAgentMediaWrites(before, next, ops)`，供 bridge 在整批业务校验后、修改任何 React/store 状态前调用，并在异步文件读取后再次核对当前修订。

- 新增或修改图片的正文地址、存储身份或批次图片时，逐项核对实际可读的本地原文件及对应规范地址。
- 临时地址、远程地址或伪造存储身份不能被普通节点操作包装成“原图已保存”；须先通过获授权的媒体导入入口保存。
- 既有原图和已上传附件可继续复用；标题/位置等无关修改不阻断旧节点缺件的修复过程。
- 视频/音频支持空占位，或引用已有且类型吻合的真实本地原文件；文本正文不作为媒体检查。
