# 本机 Codex 生图与可靠产物导入

## 前端入口

图片工作台可在「模型 API」与「本机 Agent」之间切换；本机入口选择现有画布后跳转并打开本机生图页签，保留提示词和参考图，不自动生成。Agent 的本机生成面板使用当前图片创作草稿的提示词与参考图，不要求配置图片渠道 API Key。面板显示工具、生成后端、计费来源和真实能力状态；生视频、Grok Build 等未验证能力不提供虚假选项。

先连接本机 Agent，打开目标画布，再刷新能力与当前本机 Codex 模型清单。必须明确选择清单中的模型，不能静默沿用 CLI 默认模型，也不在模型拒绝后自动切换。模型清单是当前可选目录，并不能单独证明账户可调用或生图成功。能力未验证时，用户必须明确允许当前原生任务的验证；请求可能消耗 Codex 账户额度。不会自动切换 API、自动重试或新增轮询定时器。

提交前将请求 ID、项目 ID、修订、提示词和参考图保存在浏览器本地；保存失败则不提交生成。任务绑定提交时的原项目，提交期间项目变动会阻止提交。提交结果丢失时保留意图，点击「恢复并查询原任务」，不能因暂时查询不到任务而断言没有生成。

恢复画布选择器支持查询其他项目的原任务。生成仍需打开目标画布，不能把当前页面的操作静默绑定到其他项目。

## 导入原图

已完成任务点击「保存到原画布」，前端使用 task + opaque artifact ID 读取本机登记产物，检查 PNG 签名、实际字节长度和 SHA256，保存浏览器原始文件后添加图片节点；保持原始比例，记录 thread/turn/item 来源。收到完成状态不等于已经保存到画布。实时导入只监听后端登记的 `agent_media_artifact`，不再递归扫描事件里的任意本机图片路径；刷新恢复则查询登记原任务。

导入过程中切换项目后仍写入任务原项目；重新读取最新节点，保留下载期间的用户编辑。当前画布通过 live context 导入入口追加，其他画布通过 store 更新。项目已删除则拒绝写入其他项目，等待用户恢复原项目。

节点身份由原任务与原产物决定，同一任务并发导入合并为同一操作。重试遇到已存在的正确来源节点时，只重试实际保存并补齐回执，不再下载或重复落图；来源冲突拒绝覆盖。回执仅在实际画布 flush 成功后写入。保存失败保留已下载原图和节点，显示重试导入原任务，不重新生成。

## 可复现检查

```bash
node --test web/tests/agent-media-import.test.mjs web/tests/agent-media-receipts.test.mjs web/tests/agent-media-panel.test.mjs
```

8 项产物、回执与入口行为检查通过：原项目归属与后续编辑保留、保存失败与防重复恢复、当前画布 live hook、完整性失败/项目删除/只读保护、并发与来源冲突、生成前持久化意图、回执并发保存与失败反馈，以及实际模型目录选择和提交前意图/状态同步顺序。

手动联验需要确认：真实能力查询、原生 Codex 生成与参考图编辑、请求响应丢失后恢复、切换画布后原图保存、刷新后不重复导入、导出 ZIP 并在空浏览器恢复原图。行为检查使用受控产物，不替代真实生成或额度验收。

## 外部 Codex/MCP 产物登记

外部 Codex 插件通过 `media_register_artifact` 请求登记原文件时，前端始终等待用户确认；即使关闭普通画布操作确认，该文件读取仍不自动授权。确认弹窗显示原项目、生产目录、原文件与本地副本用途。确认后沿用原请求的 claim/validate，再调用登记接口；登记完成后通过同一 opaque 产物接口、完整性检查、原图保存和回执流程导入。拒绝或过期请求不能读取文件。
