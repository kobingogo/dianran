# 统一 Agent 创作入口

> 本文记录此前实际实现与检查范围。用户已确认以[创作输入与讨论设计](CREATION-CONVERSATION-DESIGN.md)取代新增 Agent tab 和对话/作品切换设计；新方案尚待实施，本文不再作为下一轮目标交互。

## 已落地行为

- 图片、视频和画布的复合输入框增加真正的「Agent」模式。直接生图/视频保留原生成链路和各自草稿；Agent 模式可写需求、上传图片，输入 `/` 选择 Skill、输入 `@` 引用当前画布。
- 空白且没有附件、没有 Agent 草稿的直接输入框输入 `/` 时进入 Agent 模式并打开 Skill 候选；有现存草稿时通过 Agent 标签进入，避免覆盖草稿。
- 主输入框与右侧「协作详情」共用草稿、附件、Skill、模型、权限和当前会话。左右提交调用同一个控制器并阻止同一份草稿重复提交；已受理的请求清空原草稿，失败恢复草稿，侧栏关闭不停止执行。并行读取附件追加到当前草稿，会话切换或任务已开始时拒绝迟到的附件写入。
- 图片、视频页的 Agent 主区域承载消息、真实执行状态、审批、补充问题和作品。作品按原生 `threadId` 过滤；本次新增图片在执行结束后切到作品，需要审批/补充输入时优先显示对话。
- 非画布 Agent 会话首次提交准备并保存一个结果画布，同会话复用；产物沿用原任务登记、原图保存和任务中心，不混入其他会话。画布内请求继续归属当前画布。
- 结果画布映射保存在浏览器 localforage。原结果画布被删除时拒绝继续提交，要求恢复；保存失败不发送请求。即使本次没有图片产出，会话结果画布仍保留，供后续协作使用。
- 服务初始化仍显示摘要，详细 MCP 列表默认折叠。设置、Skill 安装/资源、历史和日志继续通过侧栏按需打开。
- 未连接时可以准备草稿/附件，提交需要连接且会话就绪。不会把 Skill 指令当成普通图片 API 参数发送。
- 任务定位链接优先展示原生成结果；Agent 发起图片/视频 API 工具操作时切回对应工作台结果，协作草稿仍保留。

## 本地验收

网页沿用 `cd web && npm run dev`；本机服务需要以当前源码 `cd canvas-agent && npm run dev` 启动或重启，旧发布包不包含新的会话结果目标支持。浏览器连接本机地址及 Token 后测试。

1. 图片页切到 Agent，输入 `/` 选已启用且依赖齐备的 Skill；选择与输入在协作详情里保持一致。
2. 左右各修改一次草稿与附件，收起侧栏、切换图片/视频/画布页面，再返回；核对当前会话及草稿。直接生图/视频草稿应各自保留，重新进入 Agent 应完整回显。
3. 从主输入框提交文本创作任务，核对消息、进度、停止、审批及补充问题；在侧栏继续同一会话。提交失败应恢复原草稿，不能自动重提。
4. 用创作 Skill 生成图片，确认同会话作品显示、可预览/下载/保存、任务中心可定位；再继续修改，确认复用结果画布及正确产物身份。
5. 新对话不得显示上一会话的作品；切换会话/连接期间提交应拒绝。删除原结果画布后继续提交应拒绝，而非写入其他画布。
6. 画布 Agent 模式用 `@` 引用当前节点，确认结果仍回填原画布；原直接生图、视频与原生 Codex 生图链路继续验证。

## 已检查与未确认

- 6 项前端行为回归通过：会话结果隔离、同会话复用、服务隔离、目标删除及保存失败保护。
- 3 项隔离 HTTP 行为回归通过，包含本轮新增的目标格式及当前画布冲突拦截；不启动真实 Codex。
- 独立浏览器页验证左右草稿同步、关闭侧栏、模式切换回显、跨到视频页、刷新恢复和空白 `/` 入口。使用已有 Vite 服务，未做语法检查、类型检查或构建。
- 真实 Skill 执行、付费生图、完整审批/补充输入、深色主题、手机软键盘与画布产物回填仍需用户验收；本轮未发布/部署。
