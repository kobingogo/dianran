# 创作输入、讨论与作品展示设计

## 状态与范围

本方案已获用户确认，首轮实现已进入本地工作区；未发布，尚待用户验收，不能视为真实渠道全链路验证通过。实际变更及验证范围见[实施与验收说明](CREATION-CONVERSATION-IMPLEMENTATION.md)。它补充[跨页面创作交互规则](CREATION-INTERACTION-RULES.md)，取代[统一 Agent 创作入口](AGENT-CREATION-ENTRY.md)中新增 Agent tab、对话/作品 tab 和两处同时编辑同一草稿的目标设计；旧文档仍保留为实际实现与检查记录。

## 已确认的四项选择

1. 普通输入默认直接生成，提供明确的「先讨论」入口；不根据自然语言猜测后悄悄改变提交行为。
2. 画布讨论开始后固定引用；切换选区不自动换对象，提供「引用所选节点」，支持明确引用多个节点。
3. 讨论、生成和修改默认延续当前创作会话；用户点击「新建创作」才开启新会话，原记录保存在本机浏览器。
4. 画布初次生成落在创建位置；修改结果放在原节点附近并建立关联，批量结果按组排列，默认保留原作品。

## 输入与上下文

不新增 Agent tab。图片/视频类型、对话模型、生成模型、Skill 和参考素材各自表达用途，不将选择 Skill 等同于切换运行模式。

直接创作的主按钮为「落笔生成」；用户明确进入讨论后为「发送」，输入框附近清楚显示当前用途并提供「直接生成」操作。切换用途保留草稿，不提交请求。讨论阶段由方案卡承担「确认并生成」，发送聊天消息不触发付费媒体生成。

`/` 在原输入框提供 Skill 候选，`@` 提供可用作品/节点引用，附件操作保留原入口。引用可查看、移除，模型显示具体来源与就绪状态。缺少能力、连接或素材时，在对应控件旁说明下一步，不丢草稿。

提交前冻结本轮文本、附件、引用、模型、Skill 与目标。受理与本地保存条件、未知回执和迟到回执处理沿用 R03；用户等待期间写下的新草稿不能被上一轮清空或覆盖。提交失败保留可恢复内容，不能为恢复草稿而自动再次提交。

## 图片与视频主展示区

采用一条创作记录流，不强迫用户切换「对话」与「结果」tab：

需求/讨论 → 可编辑方案 → 确认 → 原位任务状态 → 作品 → 后续修改。

直接生成只展示本轮输入摘要、任务状态和作品，不要求先讨论。对话限制阅读宽度，作品可占更大宽度；单图尊重比例，多图网格，视频展示封面及播放控件。状态卡原位替换为结果，失败保留在对应位置。作品提供预览、下载、继续修改、素材和画布操作；打开画布不是看见结果的前提。

方案确认后，之前的讨论可收起为「已确认方案 · 第 N 版 / 查看讨论」，展开不丢历史。用户正在阅读历史时，新回复或作品只提供提示，不强制滚动、切换展示或抢焦点。用户处于末尾时才跟随更新。

点击作品「继续修改」将该作品显式加入原输入框上下文；旧作品保留。预览采用可关闭浮层，关闭后恢复滚动位置和草稿；桌面固定作品预览可作为后续增强，首版不要求分栏。

输入框固定在底部，记录区独立滚动并预留输入框空间；窄屏和软键盘下仍能访问引用、模型及提交动作。

## 画布新增与讨论

| 场景 | 输入位置与结果 |
| --- | --- |
| 新增文本 | 节点内直接编辑 |
| 导入图片/视频 | 拖入或添加菜单，创建素材节点 |
| 新建图片/视频生成 | 通过现有创建入口，必要时空白处双击或「＋」，在创建位置展开复合输入；直接提交后原位展示任务与结果 |
| 围绕作品多轮讨论 | 可收起的右侧创作面板，引用对象明确 |

就地创作进入「先讨论」时，右侧接续同一份草稿、素材与目标；节点编辑器收起为摘要，由右侧承担当前编辑。返回就地输入时保留草稿，不保留两份可以互相覆盖的编辑状态。生成配置节点仍按 R03 保留可编辑配置，与临时新建草稿区分。

讨论面板收起不丢上下文、不停止任务。切换选区不静默修改当前讨论引用；显式增加引用时保留既有对象，可由用户移除。提交后目标与引用快照固定，迟到结果不能落到新选中的节点。

确认方案后，初次作品落在原创建位置；修改作品创建关联的新节点，批量按组排列。后台更新不强制移动视口或选中结果，提供查看入口。节点按钮、浮层和面板复用现有画布主题，保持扁平低视觉重量；效果图里的装饰边框、按钮底色不构成实现要求。

## 方案版本与执行

方案卡展示提示词摘要、参考素材、具体生成模型和相关参数，用户能查看完整内容并编辑。讨论产生的新方案标为「待确认」。

确认执行时冻结方案版本，绑定本轮任务与结果；执行后的方案不能原地改写，修改形成新版本。模型、引用或参数变化后需确认更新后的版本，不沿用旧确认。重复点击同一个提交不能创建重复任务。

云端模型提供建议，点染负责把已确认方案交给现有生成接口。基础流程不依赖 function calling；模型返回内容必须校验，不能作为任意代码或外部工具调用直接执行。缺少结构化输出时提供可编辑方案字段，不把无法识别的回复视为可执行计划。

## 云 API 与本机能力

| 配置 | 可用能力 |
| --- | --- |
| 只有图片/视频模型 | 直接生成，发起讨论时提示配置对话模型 |
| 只有文本模型 | 讨论和方案准备，生成时需选可用生成模型 |
| 文本与生成模型 | 完整讨论、确认、生成及后续修改 |
| 本机 Codex | 接入相同用户流程，同时按实际授权提供本机执行能力 |

对话模型与生成模型可以来自不同渠道；不因同一 API Key 或兼容协议而假设所有能力都可用。现有 `textModel` 和消息数组文本请求可复用，仍需验证渠道接口、模型权限、浏览器跨域与具体素材支持。API Key 存在浏览器本地，由前端调用；基础云端多轮讨论不假设有新增项目后端。

指令型 Skill 可以供云端讨论使用；脚本、文件、MCP 等能力必须有执行环境及对应权限。图片讨论需要具备视觉能力的对话模型；视频分析等只在适配支持时提供。文本讨论与媒体生成费用分别表达，不承诺停止本地请求等于远端停止计费。

## 会话、历史与恢复

创作会话关联讨论、方案版本、任务、作品与画布目标。图片/视频/不同画布的草稿与上下文明确隔离，不因路由切换混入其他会话。新建创作不删除旧记录；预览历史不替换当前草稿，复用需显式操作。

业务记录使用 localforage。刷新恢复原会话、方案和任务，不能自动重新生成；远端查询与结果未知按 R07 处理。本机消息继续按 threadId、turnId、itemId 归属，不把 UI 创作会话身份替代原生消息身份。涉及存储格式改动仍执行独立版本、备份、未知版本拒绝覆盖规则；本设计不授权静默历史迁移。

## 实施与验收顺序

1. 修正原输入入口：移除额外 Agent tab，明确直接生成/先讨论操作，接入 Skill 与上下文；保全现有直接生成能力。
2. 云端/本机讨论接入统一会话，加入可编辑方案与版本确认，由前端执行已有生成链路。
3. 图片/视频记录流与原位作品，串联任务中心、历史、失败与刷新恢复。
4. 画布就地新建与右侧接续草稿、固定引用、原目标落图和版本关系。
5. 验证缺少文本模型、文本/生成来自不同渠道、视觉能力不足、引用失效、重复确认、切页刷新、保存失败、主题与软键盘。真实付费输出与故障模拟分别记录，未验证渠道不承诺可用。

不新增并发、超时、重试、大小或历史保留边界。实际完成项再移入 pending-test，用户验收后更新正式功能说明。
