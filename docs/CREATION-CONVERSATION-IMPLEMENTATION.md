# 创作输入与讨论：实施与验收

本轮依据[已确认设计](CREATION-CONVERSATION-DESIGN.md)修改本地工作区，尚未发布；页面加载与接口校验不代表真实模型全链路通过。

## 实际变更

- 原输入框保留生图/视频类型，提供明确的「先讨论」「直接生成」、Skill 与引用。对话模型单独配置，聊天发送不触发媒体生成；选择 Skill 后的「准备方案」明确进入方法讨论，不执行技能脚本。
- 图片/视频主区采用创作记录，消息、版本方案、任务状态和作品同处展示。方案可编辑为新版本，确认执行绑定输入身份；媒体接口仍由浏览器直连，API Key 保存在浏览器本地。
- 会话、草稿、方案与历史使用 localforage，任务沿用既有任务中心。历史预览不更换当前输入，继续创作是明确动作；刷新不自动重发，提交状态未知只提示核对原任务。等待期间改过的输入不会被旧回执清空。
- 云端讨论复用现有文本消息数组请求。本机新增 `/agent/codex/creation-discussion`，临时只读线程以完整上下文讨论，返回回复/方案与 threadId、turnId、itemId；它不替换现有工具会话。关闭临时线程的失败不抹掉已经取得的回复。
- 工作台原位读取已有媒体回执与历史作品，不为展示而重新提交；预览、下载、继续修改、素材保存及画布交付保留既有入口。视频继续修改只引用原素材，不承诺已具备视频理解/视频编辑。
- 画布新建输入靠近选定节点；讨论面板接续同一份草稿，收起回到画布。目标固定，增加选区引用必须显式操作；刷新讨论恢复原对象，删除原对象会提示恢复或新建。本机生成填充原空图片节点或在原作品旁建立新版本，原作品保留；API 继续使用配置/结果关联。
- 开发热更新复用 React root，避免产生多份侧栏输入。未新增超时、重试、并发、附件或历史保留限制。

## 已做的验证

| 范围 | 已确认 | 尚不能据此判断 |
| --- | --- | --- |
| 图片/视频工作台 | 原输入进入讨论、返回直接生成，草稿保留，独立对话模型入口；视频原输入显示 Skill 菜单 | 云端真实多轮输出、媒体生成与结果完整性 |
| 画布 | 同一输入移到右侧、收起后回到画布、新建空草稿、历史预览不改输入；更换选区后目标固定、刷新恢复原目标与单一输入；无对话配置时失败提示并保留草稿 | 真实方案、实际素材多选、媒体落图与多版本关联 |
| 隔离 Agent HTTP | 健康检查 200，未认证 401，认证后无效讨论请求 400；未调用模型 | Codex 真实回复、图片理解及结构化输出 |

遵循项目要求，未执行语法检查、类型检查或构建。已确认现有本机 Agent 空闲后以源码版本重启，保留连接配置；17371 健康检查通过，新增讨论端点已响应参数校验。用户网页重连仍待确认，源码新增端点不应当视为已经进入已安装插件版本。

## 本地验证入口

前端当前使用 `http://127.0.0.1:3000`，本轮源码 Agent 已运行在 17371。后续启动源码版 Agent：在 `canvas-agent` 目录执行 `npm run dev`；已有 17371 服务时，先在原服务终端结束空闲服务再启动，沿用连接配置，避免打断正在运行的任务。安装版/`npx ...@latest` 尚不包含本轮端点，不能用来验证新增讨论能力。

## 用户验收清单

1. 只有文本模型时能讨论与准备方案；只有媒体模型时可直接生成，讨论明确提示配置文本能力；两个模型来自不同渠道时按各自渠道请求。
2. 用文本意见连续讨论，核对引用图片是否由实际支持视觉的模型理解；无视觉或视频分析能力时不把文字回复当作已理解素材。
3. 编辑方案生成新版本；模型、渠道、参数或引用变动后不能沿用旧确认。重复点击确认、切页与刷新不产生重复付费任务。
4. 图片/视频任务状态与作品在对应方案下展示，任务中心返回原任务；部分失败保留成功作品，保存失败只恢复原结果。
5. 新建、查看历史、继续历史不覆盖其他草稿；旧回执到达时新输入不被清空。原文件恢复失败保留任务，不自动重新生成。
6. 画布选区改变不改变当前讨论对象；显式引用支持多选。初次结果填充原位置，修改创建关联版本，原作保留；删除目标、断开和保存失败提示正确。
7. 检查深浅主题、窄屏、手机键盘、输入及记录区滚动，确保能访问模型、引用和提交动作。

真实 Skill 脚本、MCP 工具、权限审批仍由本机工具协作能力承担；基础云端讨论不提供这些执行环境，也不隐式触发它们。
