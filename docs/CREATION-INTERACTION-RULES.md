# 跨页面创作交互规则

## 范围与目标

本规则覆盖图片工作台、视频工作台、画布新建/节点编辑/批量生成，以及本机 Codex、模型 API 和现有生成插件入口。用户从提交到获取作品使用一致的任务反馈、作品操作与恢复方式；各入口保留自身必要差异。

这是设计与实施依据，不代表功能已经上线。图片方案和原型为其中的页面实例：[图片工作台方案](IMAGE-WORKBENCH-UX-PROPOSAL.md)。本规则不新增并发、超时、轮询频率、重试次数、大小或保留期限；如实施需要调整这些边界，另行说明并确认。

下一轮输入、云端/本机多轮讨论、方案确认和画布交互按用户已确认的[创作输入与讨论设计](CREATION-CONVERSATION-DESIGN.md)执行；不新增 Agent tab，旧入口作为过渡记录；本轮实际变更及未验证范围见[实施与验收说明](CREATION-CONVERSATION-IMPLEMENTATION.md)。

## 当前证据与待验证范围

图片本机任务：已在正式页面确认输入保留、无原位图片、历史和任务中心脱节、侧栏重复任务列表。此前已验证真实生成、原画布保存和刷新恢复。

视频与画布：代码检查确认已有等待卡/节点状态和原位结果；视频历史预览会回填输入，选择画布目标后完成会自动跳转；状态组件按最近同类型任务读取，任务中心仅在内存保存且依赖请求识别。视频多个恢复任务共享结果状态，存在覆盖风险；生成和保存异常在部分路径混合表达。

真实视频渠道、多任务恢复、画布并行操作、断线与保存失败仍需实机验收。代码风险不能当作已复现故障，概念原型不能当作通过验收。

## 统一规则

### R01：每轮输入、每项任务、每件作品各有身份

一次用户提交形成一个批次；批次中的独立请求形成任务，成功输出形成作品。结果卡、任务中心、历史和画布节点必须引用同一任务事实，不能用最新同类型任务、当前路由或当前选中节点推测归属。

任务保存提交时的来源入口、来源/模型、提示词、参考输入、参数和原目标。实际输入快照冻结后，用户修改草稿或换模型只影响下一轮。批量生成每项保留自身状态，批次按已完成/总数展示，局部失败不隐藏成功作品。

本机继续使用 requestId/taskId、threadId/turnId/itemId 与原项目修订关系；API 保留渠道任务身份。不能为了统一 UI 改掉现有原任务与产物安全校验。

### R02：具体模型与就绪状态在提交前明确

输入框显示具体模型与来源，例如 gpt-5.6-sol · 本机；来源分组、连接设置和模型选择职责明确。未连接、未选模型、能力不支持、引用失效或本机忙时，控件附近直接说明下一步。

重连时核验上次模型，可用则恢复；不可用要求重选，不静默换模型或改用 API。模型/能力读取期间不能把占位模型显示为可调用。复杂安装说明折叠为帮助，不把右侧助手默认打开当作生图前置步骤。

### R03：受理后处理草稿，查看作品不改草稿

| 场景 | 提交成功受理后 | 用户取消或确定未提交 | 查看历史/任务 |
| --- | --- | --- | --- |
| 图片工作台 | 移走本轮提示词与引用，保留来源/模型 | 保留原草稿 | 只查看，点击复用才回填 |
| 视频工作台 | 移走本轮镜头描述与引用，保留模型/参数 | 保留原草稿 | 只查看，点击复用才回填 |
| 画布新建输入 | 移走新建草稿，已建任务节点保留输入快照 | 保留新建草稿 | 定位作品，不改新建草稿 |
| 画布配置节点 | 保留提示词、参数与连线，这是可编辑配置 | 保留配置 | 展示原条件，与当前配置区分 |
| 已有图片/视频继续编辑 | 保留原作品，将本轮编辑输入归档；下一轮编辑草稿独立 | 保留本轮编辑草稿 | 不覆盖正在编辑的内容 |

移走草稿的条件：已收到可识别的受理回执且本地保存成功。提交中锁住本轮重复发送；可恢复的输入快照保留在任务详情。回执未知或保存失败不能直接清空。

迟到回执只能处理其对应草稿版本，不清空用户已经写下的新输入。复用提示词、条件或参考图时，若会替换现有草稿则明确提示；普通预览不弹确认，也不改输入。

### R04：先有任务反馈，再逐步替换为作品

点击提交立即在对应结果区/画布位置创建稳定占位卡，先显示正在提交，受理后显示真实生成阶段。卡片包含摘要、来源/模型、已耗时与去任务中心入口；长提示词默认折叠。

等待执行只在真实排队信息存在时显示；不伪造百分比或 ETA。图片/视频未知比例使用稳定容器，完成后尊重原始比例。轻微动画遵循减少动态效果设置，状态变化可供辅助技术感知。

占位卡原位变成图片/视频/文字，不重新堆一份完成记录。多项输出保留稳定位置和身份，不能在异步回调里用单个全局结果对象覆盖其他任务。

用户在浏览旧作品时，新结果提示可查看，不强制滚动、切换页签、选中节点或抢焦点。

### R05：生成状态、作品可用状态、保存状态分开

| 事实 | UI 表达 | 可用动作 |
| --- | --- | --- |
| 正在提交 | 正在确认是否受理 | 不重复提交 |
| 已受理/执行中 | 生成中，或真实排队阶段 | 查看进度、编辑下一轮草稿 |
| 收到成功输出 | 图片/视频已生成 | 能预览则立即展示；必要时继续读取原文件 |
| 下载/本地保存中 | 正在保存作品 | 不称为已保存，不重新生成 |
| 文件与记录保存成功 | 已保存到本机浏览器 | 预览、下载、继续创作 |
| 保存/历史/画布交付失败 | 作品已生成，具体保存步骤失败 | 抢救下载、重试对应保存步骤 |
| 远端明确失败 | 生成失败，简短原因与详情 | 修改输入或明确发起新任务 |
| 回执丢失/查询中断 | 最新状态待确认 | 查询原任务/重连，不自动新建 |

远端生成完成不等于浏览器作品保存完成，也不等于送入画布完成。任务中心显示这些事实，不能因网络请求结束而提前标记完整成功。

已有成功作品后，后续聊天 turn、统计或某个交付步骤失败，保留并展示成功作品，失败范围明确。批次可以同时有成功输出和失败任务。

### R06：三个结果入口使用相同事实，各司其职

- 工作台结果区：当前批次和用户选择查看的作品，提供直接操作。
- 历史：跨批次作品及异常记录，按媒体/来源筛选，展示真实计数；历史查看与复用分离。
- 任务中心：全站生成的活动、未解决异常及结束任务入口，显示摘要、阶段、来源、保存状态；点击定位具体作品。
- 画布：显示目标节点和输入关系，成功结果直接可见，任务细节按需展开。
- Agent 助手：对话、审批与诊断；不重复提供另一个图片结果列表作为必经入口。

任务中心的查看结果带任务身份；画布返回入口带目标项目与节点，必要时定位输入配置。清除结束任务只清除任务中心展示，不删除作品、历史或原图，也不能清掉尚待解决的保存失败/结果未知任务。

### R07：刷新与返回优先恢复本地事实

先读取已保存作品与任务，再按任务身份核对活动远端状态。恢复不会重新提交生成。活动和未解决异常应持久化；结束任务的展示与完整作品历史分开管理，不增加静默历史裁剪。

有远端任务身份且渠道支持查询的任务，沿用原身份恢复；没有身份或不支持查询时，明确说明无法自动确认，保留原输入与已保存结果。浏览器刷新不能把所有 loading 一律变成明确失败。

本机服务离线时，已保存图像/视频仍可查看和下载；不能获取的原文件提示需重连。重连核对原请求，不据“没查到”断言从未生成。

多任务恢复分别更新自己的卡和节点，不把所有任务塞进一个结果槽。恢复完成不覆盖当前草稿、当前画布或用户正在查看的旧作品。

### R08：继续创作始终保护原作品

图片：预览、下载、作为参考、存入素材、进入画布。
视频：播放/大图播放、下载、存入素材、进入画布；首帧引用等仅在已支持时提供，不承诺未接入的原生视频能力。
画布：继续编辑、再生成、转视频、用作参考都说明对象；原作品保留，新结果有独立身份和来源关系。

再生成表示使用原冻结条件创建新任务，可能消耗额度；继续编辑表示使用当前编辑条件和引用创建新结果；重试保存和查询原任务不生成新作品。

生成完成默认停留当前页面。送入指定画布后提示已送达和进入画布入口，不自动跳转；从画布发起则更新原节点关系，用户浏览其他位置时不强制拉回。

### R09：取消、停止等待与恢复必须准确命名

停止等待只停止本地等待/查询时，明确告知远端可能继续执行，并保留任务与查询入口。取消生成仅在后端支持、可以作用于具体任务且结果确认后提供；取消请求发出不能直接等同远端已取消，也不承诺退还额度。

确定失败后发起新任务与结果未知时查询原任务分开呈现；取消确认不创建假活动任务。保存失败时的主要按钮为重试保存，不是重新生成。

### R10：主页面先展示作品，管理信息按需展开

保持点染纸面、水墨与朱砂主题，沿用现有主题变量和组件。作品优先于长提示词、任务 ID 和底层登记信息；任务 ID、原始错误、查询与恢复集中在详情。

桌面与窄屏都保证输入、引用、主要操作完整可见；长输入可滚动，不把模型按钮或提交按钮挤出视口。手机单列结果，画布操作不遮挡当前作品，状态不只依赖颜色。

## 三页面落地重点

| 页面 | 沿用能力 | 首批修正 |
| --- | --- | --- |
| 图片 | Composer、已有结果卡/预览/素材动作、本机持久回执与安全落图 | 本机任务接入结果卡与任务中心；受理后移走草稿；统一历史和原位图片 |
| 视频 | 占位卡、播放器、远端任务 ID 保存、原 ID 查询 | 分任务恢复；草稿/历史分离；生成与保存分离；取消完成后的强制跳转 |
| 画布 | 结果节点、连线、生成快照、节点内反馈、视频恢复 | 状态精确绑定节点任务；新建与配置输入规则分离；任务返回定位节点；停止等待说明 |
| 任务中心 | 现有入口与任务列表 | 从请求观测补充为显式业务任务映射；绑定作品与保存阶段；刷新恢复活动/异常任务 |

请求观测可以补充下载字节与网络阶段，不能作为任务受理、作品保存或节点归属的唯一依据。先复用业务回执、视频 ID、原图存储与作品历史，不再增加一套互相漂移的任务事实。

首轮代码已落地，实际变更与验证范围见 [实施记录](./CREATION-INTERACTION-IMPLEMENTATION.md)。下面顺序保留为实施与验收依据，未实测场景不视为通过。

## 实施顺序

1. P0 任务身份与状态：确定业务任务到批次、产物、原项目/节点的映射；本机与 API 入口对接同一展示约定，建立生成/保存/未知状态边界。
2. P0 主流程：图片本机原位展示；图片/视频受理后的草稿处理；画布绑定准确状态；任务中心登记和查看结果定位。
3. P0 历史与恢复：修正视频多任务覆盖；活动/异常任务持久恢复；历史只查看不改草稿；离线读取已保存作品。
4. P1 操作与布局：统一下载、参考编辑、素材、画布入口，去掉自动跳转和重复面板，简化连接教程，补窄屏与无障碍。
5. 验收后再完善正式功能说明；实施记录先写 pending-test。当前图片原型继续作为局部示例，视频/画布不能算已完成原型或验证。

涉及 Agent 消息存储格式时，协议版本与消息存储版本保持独立，沿用项目的备份及未知版本拒绝覆盖规则；本设计不授权改动消息存储或自动迁移用户历史。

## 跨页面验收清单

| 场景 | 通过标准 |
| --- | --- |
| 单次提交/双击/确认取消 | 一轮只对应预期任务；取消不留假生成中卡，未提交草稿不丢 |
| 受理后准备下一轮 | 上轮输入可找回，新输入不被迟到回执清空 |
| 同时有两个同类任务 | 阶段、已耗时、作品分别归属；任务卡/画布节点不会串状态 |
| 批量部分失败 | 成功作品保留，失败项可定位，批次数量与历史一致 |
| 查看历史后返回 | 正在编辑的草稿、模型和引用没有被预览偷偷替换 |
| 原图下载/历史保存/落图失败 | 已生成作品仍显示；仅重试失败步骤，不创建新生成 |
| 切页、刷新、服务重启 | 恢复原任务与本地作品；不能自动重提，不能覆盖新草稿 |
| 无 ID/不支持查询 | 明确无法确认，不冒充失败或成功，保留输入与结果 |
| 工作台送入画布 | 原目标正确，保存回执真实，用户决定是否进入画布 |
| 任务中心返回画布 | 定位原节点/结果，不只打开画布首页 |
| 停止等待 | 明确远端可能继续，保留查询入口，不冒充取消成功 |
| 多页面、浅深主题、手机键盘 | 每个新页面读取本地数据后均可编辑和生成，主要操作完整可见 |

第一轮实测应覆盖本机图片、一个已配置的视频渠道、画布新建/配置编辑及跨页恢复。真实生成遵循用户已有授权与账户实际能力，不为凑状态重复生成；故障模拟与付费渠道输出分别记录。
