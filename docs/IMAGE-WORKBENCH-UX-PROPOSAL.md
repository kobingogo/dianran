# 图片工作台交互优化方案（待实施）

本页为 [跨页面创作交互规则](CREATION-INTERACTION-RULES.md) 的图片实例；共同行为与视频/画布差异以统一规则为实施依据。

## 结论与目标

本机生图已能产出图片，但工作台把本机任务的管理界面直接当成了创作结果界面。用户不得不理解画布、Agent 任务、产物登记三个概念，才能看见自己的图片。

建议保留现有视觉与复合输入框，把 API 与本机 Codex 接入同一套创作体验：写提示词 → 提交 → 结果卡等待 → 原位看到图片 → 下载或继续编辑。生成来源只影响模型、能力和费用说明，不改变用户查看作品的方式。

本方案只交付走查、规则与交互原型，不代表功能已经实现，不增加超时、重试、并发或额度限制。

## 走查范围与证据

- 本轮在用户 Chrome 正式站点检查完成后的真实本机任务、复合输入框、历史页签、右侧 Agent 与任务中心；用户刚完成一次实际生图。
- 结合此前实际提交、额度确认、原生生成、自动落图、打开结果画布与刷新恢复验证，检查提交与等待的代码路径。本轮没有额外消耗额度重新生成，也没有人为制造断网或保存失败；这些异常的设计来自现有协议与代码。
- 当前 `AgentMediaPanel` 在工作台与侧栏重复呈现纯文字任务列表；图片页本机分支没有使用原有图片结果卡。任务中心读取另一套状态；本机提交没有注册进去。历史计数仍来自 API 历史。
- `useLocalImageGeneration` 提交后没有移走本轮草稿；模型保存在临时状态，连接状态变动会清空选择；生成按钮可点击时仍可能在点击后才报告未选模型。
- 现状截图由用户提供；浏览器 DOM 复核了已完成/已保存 1/1、没有图片预览、历史 0 和空任务中心。既有结果卡、图片存储、任务中心和本机回执可复用。

## 逐段问题与优先级

| 环节 | 当前断点 | 设计决策 | 优先级 |
| --- | --- | --- | --- |
| 准备 | 来源选项、模型、连接入口层级不清；已连接却显示选择模型 | 模型按钮显示当前来源与具体模型；连接状态紧邻；缺模型时按钮提示选择，不允许到提交才报错 | P0 |
| 提交 | 提示词保留，用户容易再次提交；本轮与下一轮输入混在一起 | 成功受理并保存回执后移走本轮提示词和引用，任务卡保留完整快照；取消或确定未提交不清空 | P0 |
| 等待 | 大片空白，没有图片形态的生成中反馈 | 点击后结果区立即出现本轮卡片，先显示提交中，再按真实事件切换生成中 | P0 |
| 完成 | 只有文字，必须打开画布看图 | 同一张占位卡原位替换为图片；预览、下载、作为参考、存入素材直接可用 | P0 |
| 全局任务 | 本机任务缺席 | 提交即进入任务中心，与结果卡共享任务身份和状态；支持查看结果 | P0 |
| 历史 | 本机完成后仍显示 0；页签切换不改变列表 | 所有来源使用统一历史；计数按生成批次，来源作为筛选项 | P0 |
| 保存 | 已保存后仍显示保存按钮；生成完成与保存完成混淆 | 生成和保存状态分开；成功显示已保存，不重复提供保存动作；失败显示重试保存 | P0 |
| 继续创作 | 查询、恢复、打开画布占据主要动作 | 图片上的主要动作是查看与继续编辑；任务诊断和恢复收进详情 | P1 |
| 空间 | 长提示词横向铺满，侧栏重复，占用视口 | 结果居中成卡，摘要截断可展开；默认收起 Agent；恢复过滤仅放历史/任务详情 | P1 |
| 恢复 | 重新进入需理解原画布任务，离线时看不到已保存图 | 历史与本地图片先呈现，再查询活动任务；断开仅影响实时状态，不隐藏已保存作品 | P0 |

## 主流程规则

### 1. 准备输入

模型菜单分为「本机 Codex」「模型 API」两组。连接成功后直接列出可用模型，无须先选择来源再选择模型。未连接时本机组显示状态和「连接本机」，在输入框附近打开短连接面板；安装教程为可展开帮助，不挤占创作页面。

模型标签示例：`gpt-5.6-sol · 本机`，旁边弱化显示已连接。重连后核验上一模型是否仍可用；可用则恢复，不可用明确要求重选，不能静默替换成别的模型。

没有提示词、没有具体模型、尚未连接或能力不支持时，按钮旁明确说明原因。连接/模型刷新期间显示读取状态，不能显示一个看似可提交的默认模型。

### 2. 点击落笔生成

立即冻结本轮输入与参考图，创建可恢复的提交意图，并在结果区显示「正在提交」卡。双击只对应一次请求；此时保留输入但锁住本轮提交。额度确认取消或本地校验失败，移除未提交占位卡并保持输入。

原生任务受理且回执保存成功后：卡片切换为「生成中」，清空本轮提示词和引用，保留来源/模型；焦点回到新输入，显示「描述下一张图片…」。若用户已编辑出新的草稿，只移走旧快照对应内容，绝不覆盖新输入。

当前服务不支持立即再次生成时，允许编辑下一轮草稿，提交按钮显示「本机正在生成」。不新增队列或放宽并发限制。

响应丢失/受理不明时保留输入，按钮不直接发起相同生成；结果卡显示「提交状态待确认」，主要动作「查询原任务」。卡片与任务中心都能找回输入。

### 3. 等待图片

占位卡使用预期比例；比例未知则保持稳定的中性预览容器，图片出来后按原始比例展示。卡片包含提示词短摘要、来源/模型、真实阶段、已耗时和「可离开页面，稍后在任务中心查看」。用轻微墨点/骨架动画，不用虚假的百分比或预计完成时间。

根据真实状态呈现：正在提交、等待执行（仅存在真实排队信息时）、生成中、图片已生成/正在保存。新卡进入当前视口；用户正在浏览旧结果时提示有新任务，不强行拉回或抢焦点。

### 4. 图片完成

占位卡原位变成完整图片，支持点击大图。图片优先级高于提示词；摘要在下方最多两行，可展开完整创作信息。原始图保留，缩略图仅用于展示。

主要动作：下载、作为参考继续编辑；次要动作：存入素材、进入画布；「复用提示词」在详情或菜单中，操作后回填输入并保留已有草稿确认。任何再次生成都是明确的新任务，不与查询/保存混用。

「生成完成」与「浏览器保存」分开显示：生成完成/保存中 → 已保存到本机浏览器；已有目标画布则补充画布名称。保存失败时仍可看图和抢救下载，按钮为「重试保存」，不会再生成。需要 Agent 在线才能下载的未保存原图，明确显示此依赖。

### 5. 画布关系

图片工作台默认直接产出图片；已有原任务画布保持关联，自动落图的实现可以暂时保留，但不要求用户进入画布才能验收。图片卡的「进入画布」成为可选后续动作。

用户明确开启「在画布中创作」或从已有画布发起时，显示目标画布名。不得把当前打开的另一个画布当作原任务目标，也不得因为用户切页而覆盖任务归属。

### 6. 历史与任务中心

结果区：当前批次的进行中/完成/异常卡。历史：跨批次作品记录，可按全部、本机 Codex、模型 API 筛选；查看旧结果不自动改写正在编辑的草稿。历史计数按批次，图片张数另列。

任务中心：所有生成来源的统一进度与入口，显示图片缩略图或占位、摘要、阶段、来源、已耗时；点击「查看结果」回到原工作台并定位任务。活动任务与未解决的异常刷新后可恢复；用户清除结束任务只影响任务中心展示，不删除图片与历史。

当前任务中心声明刷新清空。第一阶段为本机持久化任务添加恢复映射并明确文案，不承诺其他 API 历史自动成为可恢复远程任务。后续统一历史适配时按各渠道真实查询能力设计。

## 状态与动作约束

| 状态 | 结果卡 | 输入/下一步 | 任务中心 |
| --- | --- | --- | --- |
| 未提交/确认取消 | 不保留生成中卡；校验错误贴近对应控件 | 保留草稿，可修改提交 | 不冒充正在生成 |
| 正在提交 | 稳定占位卡与提示词摘要 | 保留快照，防止重复提交 | 显示提交中 |
| 已受理/生成中 | 动态占位卡、真实阶段、已耗时 | 移走本轮内容，允许下一轮编辑 | 同一任务同步阶段 |
| 已生成/保存中 | 展示图片，说明保存中 | 不重新生成 | 生成完成，保存中 |
| 已保存 | 图片与直接操作 | 可作为参考/复用提示词 | 已完成，可查看结果 |
| 生成明确失败 | 失败卡、简短原因、详细信息可展开 | 恢复输入；明确再次生成可能耗费额度 | 失败，与结果卡一致 |
| 回执未知/连接中断 | 保留原任务，说明最新状态待确认 | 查询/重连；不自动重复生成 | 待确认，不能直接标失败 |
| 保存失败 | 图片可见、未保存标记、下载/重试保存 | 保护下一轮草稿 | 标记作品未保存，不能用全成功掩盖 |

取消生成只有在后端支持且确认作用于本任务时才提供；取消不承诺返还额度。连通性失败不能等同生成失败，任务阶段不能由动画或定时器推断。

## 视觉与响应式

保持点染已有纸面背景、弱边界、水墨字与朱砂主按钮。结果区域使用稳定的图片卡布局，收敛长文字；完成卡突出图片，不额外堆叠管理按钮。桌面留白服务于作品，不能留下整屏空白和顶端一行记录。

窄屏单列结果卡，操作适度换行，输入框保持可滚动和安全区间距；参考图与长提示词不能挤走提交按钮。Agent 作为独立助手，默认不随着生图任务打开，不重复展示工作台结果。

状态变化用 aria-live 通知，图片可键盘预览，图标按钮有名称；动画尊重减少动态效果设置。状态不得只靠颜色区分。原型颜色为现有主题方向演示，正式实现使用项目主题变量和现有组件。

## 实施顺序与复用范围

第一阶段 P0：本机任务适配统一结果卡与任务中心；受理后移走草稿；展示并保存图片；历史真实计数与恢复；分开生成、保存、未知状态。沿用本机任务 ID/requestId/原画布绑定，不再新增互不一致的状态表。

第二阶段 P1：缩短连接面板，完成卡的预览/下载/参考编辑/素材/画布动作一致；移除结果区与 Agent 重复列表，收起诊断信息，优化移动端。

第三阶段：任务恢复、模型重选规则、跨页往返、新旧草稿并存、保存失败抢救的端到端验收。结果区、历史、任务中心订阅同一任务事实；本机回执作为本机任务权威，API 请求记录保留各自能力边界。

复用 `useAgentMediaStore` 的持久回执与输入意图、`importAgentMedia` 的原图保存与防重复落图、图片页已有结果卡与预览/下载/素材动作、现有 Composer 与任务中心。需要统一的是展示适配和状态同步，不是重做安全提交协议。

## 完成验收标准

1. 一次点击对应一条任务，工作台与任务中心立即有相同任务卡；取消确认不会留假任务。
2. 受理后本轮提示词和引用离开输入框，但可从任务详情找回；新草稿不会被迟到回执覆盖。
3. 等待时不需打开 Agent 或手动查询就有反馈；有图后无需打开画布即可看大图和下载。
4. 本机任务出现在历史与任务中心，来源筛选/历史页签真实切换内容，不重复计数。
5. 离开、刷新、重连均恢复原任务，不触发新的生成；已保存图片离线可查看。
6. 生成完成但保存失败时显示未保存并提供抢救/重试保存；重复保存不重复创建图片节点。
7. 长提示词、参考图、桌面/窄屏、浅色/深色都不截断底部提交动作。
8. 同一任务在结果、历史、任务中心显示一致阶段；只读页面可以查看已保存作品，不能提交。
