# T01–T17 手动验收手册

本手册针对当前本地工作区。打开 `http://localhost:3000/` 验收；线上站点尚未部署本轮改动。代码实现、自动化检查、手动通过和上线是不同状态，分别记录。T11 尚有其余模板与四模式集成未完成，T12 真实环境验收未完成，T14 用户研究未完成，T17 当前仅有暂定取舍，T16 尚待配套发布。

## 测试准备与执行顺序

1. 先导出现有重要画布与素材备份。保留正常工作浏览器，用单独的浏览器配置文件测试；不要清除正常配置文件的站点数据。
2. 在测试配置文件中准备自己的图片、一个可用视频、一个无关素材。建立“验收画布”，放文字、图片、视频、连接；文案使用易辨认内容，例如“验收版本 A”。保存并导出作为基准。
3. 需要生成时，配置实际支持对应能力的渠道/模型，并自行确定本轮任务和费用预算。无渠道的项记为未测。不要为制造错误反复向真实渠道提交请求。
4. WebDAV 使用专用测试目录，插件使用已审阅的测试源码，Agent 使用专用测试会话。手机和 Docker 验收记录真实设备/环境。
5. 推荐先做不收费的 T02→T03→T04→T09→T11→T14 工具→T15，再做 T01/T05/T06；随后做 T07/T08/T13 的真实生成与 T10 双端同步，最后汇总 T12/T14/T16/T17。

全程使用同一来源：`localhost` 与 `127.0.0.1`、不同端口、浏览器配置文件均可能拥有独立存储。T04 必须在同一个配置文件的同源标签页测试；T03 独立恢复与 T10 双端冲突则使用两个独立配置文件/设备。

DevTools 的 Network 可开启 Preserve log 留存请求次数；共享截图时遮住 Authorization、Cookie、配对凭据、WebDAV 密码与敏感内容。刷新后要实际打开、播放或下载文件，不能只看缓存缩略图。

## T01：清理不误删作品

**操作**：让图片保留在画布或 Composer 草稿中；让视频保留在生成历史中。刷新一次，再删除“我的素材”中的无关条目，等待删除操作完成，再刷新并打开原画布、草稿和历史。

**通过**：仍被引用的图片可作为参考，视频可播放并下载；删除无关条目不会破坏这些文件。另测同一文件从素材列表删除但仍被画布引用，画布文件应保留。

**故障补测**：权威引用读取失败必须停止清理；真正无引用的旧文件应可清理。本页新文件有会话保护，不能用“刚上传后立即清理”判断旧文件清理失效。上述场景需隔离数据和可控故障，普通操作未覆盖时记未测，见 [作品保全记录](WORK-PRESERVATION-VALIDATION.md)。

## T02：素材保存与失败恢复

**操作**：在“我的素材”新增、修改、删除、导入；从画布节点或生成结果另存素材。每次等保存完成后刷新，核对列表、文字、文件内容。批量导入后检查条目是否重复。

**通过**：成功提示对应实际保存，刷新后内容一致，删除结果也一致。

**故障补测**：在独立测试环境让 IndexedDB 写入失败一次。新增内容应留在当前页面，显示失败而非成功；恢复存储后点“重试保存”，刷新后仍在。保存失败时“导出抢救包”应包含可读内容；读取失败时不得用空列表覆盖旧数据。断网不能模拟 IndexedDB 写入失败，见下方故障测试说明。

## T03：完整备份、独立恢复与损坏拒绝

**操作**：导出含原图、视频、文字、参数和连接的验收项目 ZIP；在另一个全新浏览器配置文件打开同一服务，导入 ZIP。再导入一次，修改第二份项目。

**通过**：两份导入项目独立，原配置文件项目不受影响；媒体可打开/播放/下载，参数和连接保留。项目 ZIP 不包含 API Key、全部素材列表或整个站点历史。

**故障补测**：复制 ZIP，解压后移除一个媒体文件或改其字节，再按原目录结构重新压缩。损坏副本应拒绝作为完整备份导入，即便测试浏览器恰好已有原文件也不能通过。不要改唯一的原始备份。项目原文件缺失时完整导出应报问题，抢救导出应列缺件并在恢复时要求确认。

## T04：多标签页编辑权

**操作**：同一测试配置文件、同一来源打开 A/B 两个标签。A 修改文字和节点位置，B 尝试修改、生成、导入和同步。A 等保存完成后点击“保存并释放编辑权”，B 点击“在此页编辑”，继续修改并刷新。

**通过**：只有一个页可编辑；B 只读时可浏览/下载但不产生业务写入或生成请求。交接后 B 读到 A 最新文字和位置，不能用旧快照覆盖。关闭持有编辑权的测试页后，另一页可主动获取。

**补测**：A 有进行中的任务或保存失败时交接应被阻止，内存内容保留。真实不支持 Web Locks 的环境应明确只读；无需为了测试关闭整个正常浏览器。

## T05：本地代理配对与目标范围

**操作**：在“设置→高级→本地代理”配置地址与目标；从仓库源码启动代理，把示例目标替换为自己的实际服务基础地址：

```bash
node canvas-proxy/index.js --origin http://localhost:3000 --target https://api.openai.com/v1
```

导入终端所示路径的当前配对 JSON，测试连接。先测试缺少配对，再测试正确配对；重启该测试代理后用旧配对测试，再导入新的文件。不要把配对文件贴到公开记录。

**通过**：缺配对/旧配对不能调用；正确配对可连接；当前未授权目标被拒绝而不是自动添加。连接代理不等于真实模型生成成功。普通配置分享/项目 ZIP 不包含配对凭据。

**补测**：伪造来源、路径越界、上游重定向用本地模拟服务验证，不能通过随意放开目标绕过。当前 npm/前端尚待成对发布，手测使用仓库源码，详见 [代理说明](../canvas-proxy/README.md)。

## T06：插件先授权、脚本凭据有范围

**操作**：画布“更多→插件→第三方”输入可审阅的测试插件 URL，点击安装。检查来源、源码、SHA-256 与高权限说明，先取消，再在确认源码安全后授权。改变该测试插件源码后检查更新是否重新审阅。测试浅/深主题与弹窗关闭。

**通过**：取消不执行源码、不安装；授权后安装；变化更新不能绕过授权，旧授权快照可核对。

**故障补测**：源码中的可观察执行标记用于证实取消零执行；脚本请求绑定渠道、越界路径、另一个测试服务时检查默认 Authorization，仅在绑定范围自动携带。用假 Key 与可控测试服务，不能把真实 Key 发给未知站点。插件仍为高权限代码，不是沙箱，详见 [T06/T16 记录](T06-T16-VALIDATION.md)。

## T07：请求未知、视频原任务恢复

**操作**：在预算内发起一个支持任务 ID 查询的视频任务，收到任务身份后停止等待或刷新，再恢复查询。Network 区分创建任务与查询请求。改动全局参数后检查原任务和失败结果保留的原参数。

**通过**：查询使用原任务 ID/渠道，不产生第二次创建 POST；停止本地等待不被描述为取消远端。新请求有可能再次计费的提醒。多图部分失败时已成功槽位保留。

**故障补测**：可控模拟渠道分别返回明确拒绝、接受后丢失响应、返回 ID 后本地保存失败。应分别显示拒绝/未知/保存失败，未知请求刷新不自动重提；ID 保存失败要有可复制身份且不能提前查询。断网发生在发送前不等于“服务已接受但响应丢失”。真实渠道是否支持恢复按其实际接口记录。

## T08：能力状态不能借用旧成功

**操作**：在新测试配置中检查未配置提示；只配置文本模型后切到图片/视频；读取模型列表；主动完成一种能力的生成后，切另一个模型、Key 或渠道再看状态。

**通过**：区分未配置、已配置、已读取模型、该能力有成功记录；文本成功不代表图片成功，读取列表不代表生成成功，更换条件不能借用旧证据。不操作生成时不应出现后台付费验证请求。

## T09：存储与数据路径说明

**操作**：“设置→高级→本地存储”核对来源隔离、保存与备份、Key/代理/Agent/WebDAV 数据路径，点击申请持久化。另一个空配置文件导入项目 ZIP，确认渠道 Key 没跟着导入。

**通过**：申请成功、拒绝或不支持均有合理状态；拒绝不阻止创作/备份；文案不承诺云同步或全站备份。浏览器许可是实际结果，不要求所有设备都获批。

## T10：WebDAV 双端冲突与备份恢复

**操作**：A/B 两独立配置文件或设备使用同一专用 WebDAV 目录。先同步同一项目；断开同步分别修改同一文字为 A/B，再依次同步，检查原项目和冲突副本。另做一端删项目、一端修改项目。A 同步后修改内容，再点击“恢复同步前备份”。

**通过**：双方作品可找到并打开/导出，不只按时间戳选一方；删除/编辑冲突保留编辑副本。恢复重新加载当前页，可读到同步前媒体并继续编辑，恢复本地不改远端。

**补测**：服务须实际支持强 ETag 与条件写入；不支持时明确停止也符合保护设计，但不能记为“该服务同步通过”。服务断开/上传竞争时报告哪些域已完成，不应笼统全量成功。同步前备份也存在该浏览器来源中，清除站点数据会删除它，详见 [T10 记录](T10-VALIDATION.md)。

## T11：模板填写、独立建图与预览

**操作**：首页“活动海报”填写独特文案，选择创建并审阅工作流；核对文案节点、输入连接和预览实际尺寸/数量。再创建一次模板并只改第二份。产品图组分别试未提供参考和提供自己的参考。

**通过**：填写内容实际进图，重复实例互不覆盖；产品图组要求并连接真实参考；仅创建/预览不产生生成请求，执行前可审阅参数与调用数。活动海报当前预览三步、共四次逻辑生成请求。

**未完成范围**：其他模板逐项执行、四模式工作流与模板 ZIP 尚有集成/验收依赖。没有入口的能力记录待开发/集成，不能因为海报通过勾选全部模板。

## T12：真实环境矩阵

按 [22 场景矩阵](T12-ACCEPTANCE-MATRIX.md) 填写实际渠道/模型、手机、Agent、Docker 结果。手机需真机键盘、触摸、上传、后台返回；桌面模拟视口不算真机。Docker 需实际部署下首页、深层路由、封面、模板、插件与 API 边界结果。

**通过**：本轮声明支持的组合均有实际结果与问题记录。没有的渠道/设备、未集成的四模式保持未测/等待；Agent 对话归属/恢复通过也不能替代 AG01–AG06 专项尚未实施的保护。

## T13：完整作品任务

**操作**：自己的产品参考→产品图组→预算内生成候选→“比较并采用”→采用第二张→创建分支/继续编辑→调整尺寸形成延展→完整项目 ZIP→空配置文件恢复。

**通过**：能看见真实参考和参数，采用实际改变原图组主图，分支不覆盖原版，弹窗可正常关闭；恢复后媒体、关系和参数仍在。分别记录链路通过与作品质量，主体一致性不达标需记录，不能由按钮可用推断质量通过。

## T14：自愿诊断工具与用户研究

**工具操作**：“本地存储→自愿本地诊断”，开始记录，点“记录一次需要帮助”，导出 JSON；检查只有类别、时间、耗时，无提示词、Key、渠道或项目身份。停止、刷新后检查未自动继续记录；删除记录后再检查。

**研究操作**：取得参与者同意，分别观察首次配置、熟练迭代、备份恢复任务；记录目标、完成与否、停顿、求助和获准引用的反馈。

**通过**：工具行为与隐私范围符合说明；研究有真实记录及阻碍分析。自己点击诊断工具只算工具验收，不算用户研究完成，不从小样本推断总体转化率。

## T15：真实工程性能

**操作**：选择一个日常工程和一个实际较大的工程，记录设备/浏览器、节点数、媒体数量/大小。观察打开、拖动、保存、ZIP 导出；用 DevTools Performance 记录导出期间主线程与交互，然后在空配置文件恢复 ZIP。

**通过**：导出不破坏作品，恢复完整；记录实际交互停顿和导出耗时。ZIP Worker 的目标是减少主线程卡顿，不要求总耗时每次更短。不把模拟基线数值当通用性能阈值，需同场景对比，见 [性能基线](T15-PERFORMANCE-BASELINE.md)。

## T16：统计确认与去重

**当前可手测**：查看提示词页统计说明；开发模式不发送统计，无新版 API 的静态/旧部署应显示不可用。Network 核对统计没有上传创作内容、文件或 Key。

**配套发布后补测**：在专用环境生成内置素材复制/应用事件，观察稳定 batchId 与匹配 accepted 回执；离线/拒绝/响应丢失后同一批次不被丢弃。相同批次重发与聚合不重复累计，不同内容冒用同一身份应冲突。

**判定**：当前可验收停用边界，不能在 localhost 开发模式或线上旧 API 上宣布统计完整通过。沿用原发送频率，不通过不断刷新/等待猜测重试；需要可控 API/测试队列复核，见 [统计记录](T06-T16-VALIDATION.md)。

## T17：决策验收

阅读 [扩展决策](T17-EXTENSION-DECISIONS.md)，逐项核对需求、保留/暂缓理由、证据门槛与下一切片；使用 T12/T13 实际任务、T14 用户观察和 T15 性能结果修订，选择下一项具体范围。

**通过**：选择有证据支撑、范围与验收明确，其他需求仍保留。此任务交付决策，不要求出现五个新功能入口；当前暂定材料齐备，最终决定尚待真实证据。

## 保存失败等故障如何测

Network 离线只影响网络，不会制造 IndexedDB 失败；清除站点数据只会删除数据，也不能代表保存失败恢复通过。不要填满日常磁盘或修改正常浏览器数据库。

以下让开发者在隔离环境协助复现并录制结果：IndexedDB 一次写入/读取失败、视频收到 ID 后保存失败、服务接受请求后响应丢失、WebDAV CAS 竞争、统计接受后响应丢失和聚合删除失败。这些已有针对性自动化检查，但对应界面仍需核验。未复现就记录未测，不能从正常路径推断异常路径通过。
