# T07–T08：请求恢复与生成能力记录

## 本次变更

- 请求明确区分未提交、渠道明确拒绝、结果未知。生成请求的网络断开、等待取消、超时或缺少可确认结果，不证明远端没有接受，也不证明没有计费。
- 前置渠道配置、素材准备与本地代理授权失败保留未提交原因；HTTP 4xx 明确拒绝与 HTTP 408、5xx 的不确定情况分开处理。流式请求保留 HTTP 状态。既有端点回退最后一次响应丢失时保留最后尝试的不确定结果，不拿旧的端点拒绝覆盖它。
- 图片与视频工作台先保存原意图，再发生成请求。视频收到 ID 后必须完成本地保存，才开始查询。保存失败时当前页面和异常保留原 ID；应先复制 ID 抢救，修复保存后取原任务状态。
- 视频查询绑定原模型、渠道身份与服务地址；渠道或地址移除、变化时拦截。已持久化的 pending 视频沿用原 ID 查询；未知且没有 ID 的请求刷新后不会自动重新提交。查询中断保留 ID，用户可明确选择取状态。
- 新请求与取任务状态分别标注。图片或画布失败结果重新生成前弹窗说明可能重复计费；取原视频状态不创建新请求。停止本地等待不称为取消远端任务。
- 图片成功槽位按既有保存队列串行写入原批次历史。未完成槽位仍表示未知，原成功图片与参数快照保留；保存错误不会把已返回作品当作渠道拒绝。
- 能力证据存放在独立浏览器业务存储中，SHA-256 身份包含渠道 ID、地址、API 格式、Key、模型与能力，记录本身不保存 Key 明文。切模型或 Key 后不能借用旧成功记录。
- 首页和 Composer 分开表达未配置、已配置、已读取模型、此能力有生成成功记录。默认模型占位名称不冒充可调用模型；未配置 chip 显示“未配置 · 选择模型”。配置向导完成后提示主动提交第一件作品，不后台发送付费验证。
- 生成成功来自主动调用得到非空输出；空文本和空音频不产生首次成功。能力记录保存失败不吞掉已完成作品，页面提示记录尚未保存，既有队列保留快照并支持显式 flush。编辑权交接前会刷新这份队列。

没有新加超时、重试次数、并发、大小或任务裁剪边界；沿用现有等待与查询机制，没有声称渠道具备通用幂等能力。脚本视频的一次调用结果仍按既有方式管理；没有伪造可跨刷新恢复的远端任务 ID。

## 可复现行为检查

在仓库根目录运行：

```bash
node --test web/tests/request-readiness.test.mjs
```

本次 9 项检查通过，覆盖：

1. 响应丢失、停止本地等待、408/502 为结果未知；明确 400/401/403/429 拒绝保留语义。
2. 文本模型不能代表生图就绪，默认模型占位不代表已配置。
3. 成功记录按模型、渠道及 Key 隔离，持久化记录不含 Key 明文。
4. 并行成功记录不会互相覆盖；读取模型不产生生成成功记录；持久化失败不会让已付费成功结果报为请求失败。
5. 生成失败不会伪造首次成功。
6. 视频创建保留原 ID 与模型身份，查询不再 POST，渠道移除或地址改变不继续查询到其他渠道。
7. 视频响应丢失或成功响应缺 ID 不误判拒绝。
8. ID 保存失败异常保留原任务且不继续查询；真实 fetch 跟踪网络丢失和缺 ID 状态。
9. 本地前置校验、空 Key 与引用文件准备失败不暗示远端已接受，缺 Key 时没有生成网络请求。

测试使用隔离存储和模型响应，不调用付费模型；没有执行语法检查、类型检查或构建。

## 仍需实际验收

- 在真实渠道允许的预算内，分别验证图片、视频、文本和音频；模型列表读取成功不能代替创作成功。
- 在独立测试页面模拟创建请求发出后丢失响应、收到 ID 后 IndexedDB 写入失败、查询断网、取消等待以及明确鉴权拒绝。核对 UI 与历史、复制原 ID、恢复保存后查询的体验。
- 多图逐槽成功后刷新，核对已保存图片、未知槽位提示和原参数，再手动选择新请求并确认计费提醒。
- 用错误 Key 读取模型和生成，切换同名模型所在渠道、改变 Key，核对能力提示不会沿用旧验证。
- 本文的自动化检查覆盖核心逻辑，不宣称所有真实供应商均支持 ID 查询、请求去重或远端取消。未知且没有 ID 时无法保证通用恢复，需要保留不确定状态并由用户决定是否提交新请求。
