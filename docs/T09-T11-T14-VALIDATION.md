# T09、T11 与 T14 交付记录

## T09 数据路径与浏览器存储

首页、设置、README 与快速开始分开说明本机保存、备份和服务调用。作品主要留在当前浏览器来源；Key 调用时发往渠道，代理、Agent 与 WebDAV 按各自授权处理内容。更换设备、浏览器、域名或端口不自动迁走作品。项目 ZIP 的范围与完整性以清单为准，不等于全部站点备份。

存储设置显示浏览器持久化状态并允许主动申请，未支持或未获批不阻止创作和备份。不把持久化许可称为备份；未知配额显示为空占用估计，不产生除零百分比。代理说明与源码启动命令同步为配对协议 2。

Dockerfile 增加构建时需要的共享代理策略文件，修正使用文档中主应用仍是 Next.js 的过时描述。本轮未执行 Docker 构建或生产部署，资源路径与 Worker 打包仍待实际验收。

## T11 模板预览

首页模板先打开输入审阅，展示所需生图能力、配置数与逻辑请求数，可修改文字输入。五个模板均提供“创建画布并审阅工作流”；扩展整合与替身执行证据见 [T11 整合记录](T11-INTEGRATION-VALIDATION.md)，真实渠道执行仍待验收。

模板建图为独立节点，文字引用替换到当前实例；输入边明确为 input，比例使用既有像素预设。产品图组必须上传自己的参考图，并为每个目标配置连接真实参考。上传在每次实例化时生成新的本机文件身份。未知输入、损坏关系及缺少产品参考在创建前拦截。

创建后等待画布实际保存，工作流提供预览全部配置及选定范围，沿用现有参数预检、确认、意图保存和执行；创建、填写、修改、预览都不主动调用模型。活动海报是三步、四次逻辑请求，模型实际尺寸以预览为准，不能把设计比例当作所有渠道必然支持的像素。

独立 Chromium 模拟渠道检查通过：填写活动文案、创建四节点/三输入边、预览三步四次请求，生成网络调用为零。浏览器继续验证存储说明与自愿诊断，不接触用户 localhost:3000 页面或付费模型。重放脚本为 `web/tests/t09-t11-browser-check.js`，只在独立 localhost:3001 环境运行；内含虚构渠道配置，不用于用户浏览器。

真实生成、部分失败后的原成功候选保留、产品主体一致性及其他模板执行仍需按 T12 验收；四模式已从明确草稿基线整合到当前工作区，但尚未合并主线或发布，不以替身执行代替真实渠道验收。

## T14 自愿本地诊断与研究准备

设置新增自愿诊断，默认关闭，开始后仅当前页面会话记录固定操作类别、时间和可选耗时。记录不含提示词、文件、Key、模型/渠道或项目身份，不上传；停止或刷新后不继续记录，可主动导出和删除。记录使用独立 localforage 存储，全局状态放在 stores；失败不影响生成结果。

已接入生成成功/结果未知、模板创建、候选采用和项目备份导出/恢复；“需要帮助”由参与者主动点击记录。操作次数只描述该次自愿会话，不能推算总体转化率，也不能把开发者模拟测试当成真实用户反馈。

**T14 用户研究尚未完成。** 需要真实参与者同意与使用场景；没有访谈原话、样本结论或虚构成功率。研究操作如下：

1. 招募有 Key 的首次用户、熟练迭代用户、长期备份用户，说明记录范围、用途和可撤回方式；手机方向需真实手机样本。
2. 在同意后开始本地诊断，观察首次成功、参考复用、比较采用、分支、导出与恢复；记录停顿与求助位置，作品内容和访谈另行获准再保留。
3. 用匿名参与编号记录设备/浏览器、任务目标、是否完成、阻碍、帮助方式与参与者允许使用的原话。未取得的字段留空，不自行补写。
4. 结束会话停止记录，参与者审阅后自愿提供脱敏 JSON；按实际最高频阻碍决定是否调整定位，不预设提升比例。
