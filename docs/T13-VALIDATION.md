# T13 首个创作切片验收

## 当前接通的路径

自己的产品参考图 → product-set 模板建立参考关系与候选配置 → 使用自己配置的渠道生成 → 图组「比较并采用」 → 采用主图 / 创建分支副本 → 沿用继续编辑，修改尺寸产生延展分支 → 完整项目 ZIP 导出与恢复。

T13 复用既有 `primaryImageId`、`setBatchPrimary`、`duplicateBatchImage`，没有增加第二套 adopted 状态。主图采用同步更新图组 content、storageKey、原始尺寸、字节数与 MIME；尊重原比例。候选副本携带原生成条件和来源，打开已有编辑入口。

新增图组比较弹窗，按原比例查看全部候选，显示当前主图、实际像素尺寸和已有生成模型、请求尺寸、质量、提示词。生成失败或尚无输出的槽位保留其真实状态，不能采用空内容。明确「获取灵感」与「按原条件尝试」所需的模型/参考条件不同，不承诺主体一致性。

现有展开图组已可并列查看和设主图；本次补集中比较入口以降低大画布逐项查找成本，不合并草稿 PR、不复制其架构。模板的参考必填与继续编辑、完整 ZIP/恢复由既有 T03/T11 改动提供。

## 待实际验收

独立 Chromium 使用两张模拟候选与一个失败槽位，已验证打开比较、采用第二张图后原图组的 primaryImageId 实际更新、关闭弹窗后继续操作插件管理器，页面无运行异常。复核中修复了 Portal 弹窗事件冒泡触发画布拖动/指针捕获的问题。可复现脚本为 `web/tests/t06-t13-browser-check.js`，结果为 `output/playwright/t06-t13-browser-result.txt`。

没有运行构建、类型检查或付费生成。主题、分支副本与完整创作切片仍需使用自己的产品参考和真实渠道执行，记录实际模型、输入参考、请求参数、输出质量及不一致情况。T12 当前能力证据并不替代真实成品评估。

尚未把界面接通视为输出质量通过，也未宣称所有用户均需要电商场景。
