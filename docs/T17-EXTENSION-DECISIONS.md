## 接下来的具体顺序

1. 先完成 T12 已选渠道/设备/Agent/部署的真实验收与 T13 完整创作切片，确认 R1–R4 保护和恢复在真实条件下成立。四模式验收需要草稿 PR #1 的明确集成基线，不可用当前轻量比较界面替代。
2. 按 T14 招募有 Key 的首次用户、熟练迭代用户与长期备份用户，在获准记录后观察成功、复用、采用、导出/恢复及求助。需要手机/跨设备方向时补真实样本；不预设样本能推算总体转化率。
3. 完成 T15 典型/重度项目的设备、数量/大小与测量条件记录，判断实际瓶颈；没有瓶颈证据就保留基线和无需优化结论，不新增经验上限。
4. 由负责人以这些证据复审上表。若重复插件动作需求成立，优先考虑单动作工作流切片；若证据首先指向后台执行、Claude 或冲突协作，则按实际阻碍调整顺序。此排序是条件性候选，不是“用户最需要插件动作”的研究结论。
5. 只对被批准的一项切片补范围、权限、预算和验收，复用既有步骤/快照/状态；其他候选继续保留，避免全部一起启动。

## 外部输入和判定规则

当前等待：项目负责人选定真实渠道/模型与测试费用范围，提供参考素材使用许可、设备和本地测试服务；协助招募并授权记录真实用户样本；对后续扩展的具体任务、权限和投入作选择。研究资料必须真实取得且允许记录，不能用推测填充访谈原话。

每次改变决定补上具体证据、受影响用户任务、方案与限制，不仅写“需求有价值”。需求价值和实现质量分开判断；保留需求不等于可以合并现有实现，暂缓实现也不否定需求。任何扩展合并仍需按项目约定先说明修复、验证、风险与冲突并取得明确同意。
