# 可靠性与工作流验收记录

## 交付范围

原有 #3–#7 已按依赖合并至 main（`2066793`），初次审查的复制状态、中文提示词身份与重复 ID 修复在其中。新分支 `feat/creation-reliability-workflows` 按确认顺序补齐检查、可靠性、完整过程投递和工作流 MVP。

- 保存：沿用 400ms 合并写入，将 IndexedDB 成功作为「已保存」的依据。写入串行，失败保留最新快照；可重试和导出内存中的项目。读取失败拒绝覆盖，画布存储不回退 localStorage。有未落盘修改时关闭页面会提示，提示不等于浏览器关闭时必能完成异步写入。
- 重试：工作台重试原提交，画布优先使用结果自身的输入快照；再生成的原始编辑内容不取当前来源配置。快照仅包含参数、提示词与文件身份，不包含 Key。
- 视频恢复：先保存 ID，再轮询；查询失败保留原任务。新任务记录渠道地址，恢复时地址变化先阻止请求。已有未记录地址的任务仍按已有渠道身份查询。离开画布只终止本地查询，不保证撤销远端任务。
- 投递：默认仅结果，可勾选完整过程。过程图含参考图片、配置、结果及关系；重复投递幂等，仅结果可以补齐过程。原始文件缺失时明确失败。
- 工作流：选定配置及显式 input/generation 依赖，预览顺序、范围、模型、实际参数和逻辑生成请求数，确认后创建本轮配置/结果并沿用现有执行逻辑。输入复制自批准的计划，原作品保留，改参数不自动执行。每步调用前持久化状态；部分失败停止下游，已成功步骤不重提。
- 中断：原结果节点完成重试或恢复后，可核对已保存结果并继续未执行步骤。未知任务、缺失输出和未完整成功批次不能跳过核实。无法恢复的步骤由用户重新规划或明确重新生成，执行器不自动重提。
- 模板：保存到同一 IndexedDB 的独立模板 key，展开为独立节点/连线。只保留必要文件身份和配置，去除任务与 blob URL，文件清理会保留模板引用。
- Agent：正常消息中的 `dianran-plan` 白名单格式进入同一预览与确认入口；审阅不改画布、不调用生成。步骤产物保留 threadId/turnId/itemId；不改变通信和历史存储协议。

## 可复现命令

环境：Node 22、Bun 1.4.2、已安装 Chrome。没有全局 Bun 时可用 `npx --yes --package=bun bun` 替代 `bun`。

```bash
cd web
bun install --frozen-lockfile
bun run typecheck
bun test
bun run build
cd ../canvas-agent
npm ci
npm test
cd ..
node --test brand/pipeline/prompt-key.test.mjs
node brand/pipeline/validate.mjs
bash scripts/check-browser.sh
```

浏览器脚本固定使用 Playwright CLI 0.1.22，在各自隔离会话运行，检查端口 4317 空闲后启动和清理自身 Vite 进程。业务脚本位于 `output/playwright/*-regression.js`；结果 JSON 在 `.playwright-cli/`，截图在 `output/playwright/evidence/`。CI 上传这些证据，不上传测试用 Key；脚本配置只含 mock-key。
