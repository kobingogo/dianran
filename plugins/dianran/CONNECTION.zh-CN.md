# 点染画布是怎么“连上”你电脑里的 Agent 的（给非技术同学的说明）

> 适用版本：@kobinflow/canvas-agent 0.7.0、Codex 插件 `dianran`（2026-10-04）

## 一句话版

点染网页本身只是一个运行在浏览器里的画布；真正能“动手”的是你电脑上跑着的一个小程序（本地 Agent）。网页通过 `http://127.0.0.1:17371` 这个**只在你自己电脑上有效**的地址和它说话，并用一串 **Connect token（连接口令）** 证明“我是被允许的那个网页”。

## 都有哪些角色，各自在哪里运行

| 角色 | 运行在哪 | 干什么 |
|---|---|---|
| 点染网页（dianran.vercel.app） | 你的浏览器 | 画布、生图、提示词库。网页文件来自我们的服务器，但画布内容默认保存在你浏览器本地。 |
| 本地 Agent（`npx @kobinflow/canvas-agent`） | 你的电脑，一个终端进程 | 在 `127.0.0.1:17371` 开一个小服务器；把“读取画布 / 加节点 / 生成图片”等操作转发给网页，网页执行后再把结果回传。 |
| MCP 进程（`canvas-agent mcp`） | 你的电脑，由 Codex 自动启动 | 把 34 个画布工具（读画布、建节点、连线、生图生视频、搜提示词、管理素材、切换页面等）“翻译”给 Codex 用；它本身不碰网页，只是把调用转交给本地 Agent。 |
| Codex（`codex` 命令或 Codex 内置的 app-server） | 你的电脑 | 真正理解你的需求、决定调用哪些工具的 AI 助手。 |

我们的服务器（Vercel）**不在这条链路里**：网页和本地 Agent 之间的通信直接发生在你的电脑内部，不经过任何云端中转。

## 网页是怎么找到本地 Agent 的

1. **地址：自动探测。** 网页会尝试访问 `http://127.0.0.1:17371/health` 和 `/config`。这两个接口是公开的，只回答“我在、我的地址是这个、我设置了口令”，**不会返回口令本身**。
2. **口令：不会自动下发。** 拿到口令只有两种方式：
   - 在 Codex 里说“打开点染画布”，插件会打开一个形如 `https://dianran.vercel.app/canvas?mode=new#agentUrl=…&agentToken=…` 的链接。注意口令放在 `#` 后面（URL hash），**浏览器不会把 # 后面的内容发给我们的服务器**；网页读取后会立刻从地址栏里抹掉它，然后保存在本机浏览器里。
   - 或者你从终端输出里复制 Connect token，手动粘贴到“Agent 连接”面板。
3. **连上之后：** 网页用口令订阅 `/events`（一条一直开着的消息通道），本地 Agent 有活要干时就通过它把指令推给网页，网页执行完再把结果 POST 回去。

## 口令保护了什么

除了 `/health`、`/config` 这两个“打招呼”接口，其余所有接口（读写画布、执行工具、驱动 Codex、批准权限、读取本地图片等）都必须带上正确口令，否则返回 401。

另外还有一层“认门”（来源绑定）：**第一个用正确口令连上来的网站域名会被记住**（写进 `~/.dianran/canvas-agent.json` 的 `origins`），之后别的网站即使拿着口令来，也会被拒绝（403）。

## 让网页访问 localhost 有什么风险（实话实说）

- `127.0.0.1` 意味着只有你这台电脑能访问，局域网和公网上的人连不上。
- 但**你在浏览器里打开的任何网页**理论上都能向 `127.0.0.1:17371` 发请求。所以任何网站都可以通过 `/health` 探测到“这台电脑在跑点染 Agent”——仅此而已，拿不到画布内容。
- 真正需要保护的是口令。口令一旦泄露（比如截图、录屏、把带 `#agentToken=` 的链接发给别人），再加上对方能让请求看起来来自已绑定的网站，就可能读写你的画布；如果你开着 Codex 模式并选了“自动 / 完全访问”权限，甚至可能让 Codex 在你电脑上执行命令、读取本地图片文件。
- 建议：
  - 把 Connect token 当密码看待，不要截图分享，不要把带口令的链接发给别人。
  - 不用的时候在终端按 Ctrl+C 关掉本地 Agent。
  - 怀疑泄露时，删除 `~/.dianran/canvas-agent.json`，重启本地 Agent 会生成新口令并清空已绑定的网站，然后重新连接。
  - Codex 权限尽量用“每次询问”，只在信任的任务里临时切到自动。

## Codex 模式额外带来了什么

不开 Codex 时，本地 Agent 只是“传话员”：外部 AI（比如你在 Codex 终端里对话）通过 MCP 工具操作画布。

开启 Codex 模式后，本地 Agent 会在你电脑上启动 Codex 的 app-server，并把点染 MCP（名字 `dianran`）注入给它。这样你可以**直接在点染网页右侧的 Agent 面板里和 Codex 聊天**，让它规划并批量操作画布（建节点、写提示词、连线、发起生图/生视频）。它会用你本机 Codex 的登录和额度。权限分三档：

- 每次询问（推荐）：每个需要权限的动作都会在网页侧边栏弹出确认。
- 自动：常规动作自动执行。
- 完全访问：Codex 可以不经确认运行命令，风险最高。

无论哪档，写入画布的操作都会在网页里显示出来，可以随时中断。
